# 우선순위 모델 설계 — 2026-10-31 (v2: 라벨 희소 상황의 정석 반영)

근거: `research_notes/label_scarce_learning_comparison.md`, `research_notes/tigta_2025_308_022_ai_case_selection.md`

## 자리
모델은 플래그를 **만들지 않는다**. 규칙 엔진이 만든 플래그의 **순서를 정한다**(재정렬기). 예측 대상은 "이 거래가 위반으로 확정될 확률".
규칙 판정, 취소 제거, OCR, 자연어 번역에는 쓰지 않는다. 규칙과 임계치는 항상 사람이 바꾼다.

## 시연용과 운영용은 같은 기계
구조·코드·구성요소가 같다. 다른 것은 **정답(라벨)의 출처** 하나이며 `--label-source` 인자로 강제한다(기본값 없음).

| 단계 | 정답 수 | 라벨 출처 | 비고 |
|---|---|---|---|
| 0 (지금, 시연) | 0 | `weak`: 규칙 투표. violation 등급 규칙은 강한 투표, advisory는 약한 투표, 독립 규칙 여러 개 동시면 신뢰도↑ → 거래별 위반 확률 | 실데이터 분포를 배움. 결과가 규칙 순서와 95% 이상 같으면 "배운 게 없다"로 판정 |
| 0.5 | 윤경팀 과거 결과 있을 때 | `import`: 과거 점검 결과 엑셀(거래 식별 키, 판정, 판정일, 사유)을 라벨로 적재 | 넘기는 날 "귀 팀 데이터로 바로 학습"이 되는 입구 |
| 1 | 100~300 | `reviews --reviewers …`: 지정 검토자의 최신 결정 | 무작위 표본 판정을 깨끗한 검증셋으로 고정. 규칙별 실제 정밀도 표가 처음 생김 |
| 2 | 300~1,000 | reviews + 준지도(scikit-learn 자기 학습, weak 결과는 사전분포로만) | 검증셋이 더 안 오르면 중단 |
| 3 | 1,000+ | reviews만 (지도학습) | 규칙은 설명·드리프트 경보로 남김 |

**합성 79건은 어느 단계에서도 학습에 쓰지 않는다.** 규칙 명세로부터 만들어졌고 임계치도 그것으로 맞췄으므로 학습·평가 모두 순환이다. 역할은 규칙 회귀 테스트(재현율 100% 유지)뿐.
개발팀의 테스트 판정은 reviewer 이름으로 구분해 어떤 단계에서도 제외한다.

## 피처: 규칙과 분리
정답이 규칙에서 왔으므로 입력까지 규칙이면 모델은 규칙을 베낀다. 피처는 **규칙이 보지 않는 정보**로 구성한다.
- 사용자 프로필: 월평균 대비 배수, 심야(21시 이후)·휴일 사용 비율, 업종 구성, 거래 빈도
- 동료 비교: 같은 부서·직급 중앙값 대비 배수, 같은 계정×업종 백분위
- 가맹점: 전사에서 그 가맹점을 쓰는 직원 수(희소도), 가맹점 평균 금액 대비
- 시퀀스: 직전·직후 거래 간격(분), 같은 날 거래 수, 같은 날 지역 수
- 이력: 과거 플래그 수, 과거 확정 수(운영 단계), 선례 유사도 최고점
- 맥락: 시간대, 요일, 금액(로그), 증빙 여부, 출장·휴가 여부
**넣지 않는 것**: 규칙별 걸림 여부, 걸린 규칙 수, 검토자 이름·검토 시각(결과 이후 정보).
규칙 점수(등급별 가중 합)는 **별도 앙상블 구성원**으로 두어 "모델이 규칙 외에 더 찾은 것"을 측정 가능하게 한다.

## 학습·검증
- 기준선 1: 규칙 수 × 금액 단순 정렬. 기준선 2: 로지스틱 회귀. 본 모델: XGBoost. **기준선보다 나을 때만 채택**하고 비교 수치를 항상 함께 보여준다(TIGTA 지적 2 대응).
- 시간순 분할: 2월 학습 → 3월 검증. 무작위 분할 금지.
- 지표: 상위 K건 정밀도(K = 검토 처리량), PR-AUC. 단계 1부터는 **무작위 표본 판정**에서의 지표를 주 지표로(규칙이 고른 세계 밖의 중립 시험지).
- 모델이 규칙과 다른 순서를 내놓은 상위 건은 발굴 입구(docs/DISCOVERY_LOOP.md 입구 2).
- 산출물: `models/<version>/model.pkl` + `manifest.json`(피처 목록, 라벨 출처, 검토자 목록, 학습 기간, 지표, 기준선 대비, 데이터 스냅샷 해시).

## 적용
`score_tx.py` → `tx_score(tx_id, score, model_version)`. 목록 정렬 옵션 "모델 점수". 점수 옆에 기여 상위 피처 3개(사람 말로).

## 검토 큐 구성 (라벨 품질을 위해)
걸린 더미 (100−p)% + 안 걸린 더미 무작위 p% (출발 10~20%). 큐의 각 건에 "왜 올라왔나"(규칙/무작위/모델 불확실)와 선택 확률을 기록한다. 이 기록 없이는 쌓인 라벨로 공정한 평가가 불가능하다.

## 시연 시 반드시 붙이는 문구
"이 점수는 윤리경영팀 판정이 없는 상태에서 규칙들의 합의로 만든 임시 정답으로 학습한 시연용입니다. 실제 성능은 판정이 쌓인 뒤 같은 스크립트로 재학습하여 단순 정렬 대비로 측정됩니다."

## 구현 기록 — labels v1 (2026-11-01)
- 파일: `packs/corp_card/weak_labels.yaml`, `scripts/labels.py`, `tests/test_labels.py`. 테이블 `labels(tx_id, prob, label_source, source_version, n_votes, clusters_hit, created_at)`, 출처별 교체 저장.
- weak: 규칙별 p = p_rule 또는 p_tier(violation 0.6 / advisory 0.2), 군집 10개 안에서는 max, 군집 사이는 noisy-OR `1−(1−prior)·Π(1−p_c)`, prior 0.02. 결과(실데이터 29,433건): 평균 0.126, >0.5 비율 11.5%, prior 그대로 70.9%. 합성 위반 평균 0.535 vs 합성 정상 0.084(PASS). LORO 최대 비중 R16 0.229, R01 0.214, R02 0.166(지배 없음, 임계 0.5). #11012 = 0.843(entertain+time). 재실행 해시 동일.
- reviews: `--reviewers` 필수, superseded 제외, hold 제외, tx 단위 "위반 하나라도 1". import: xlsx/csv, tx_id 또는 (emp_id, 날짜, total) 매칭, 모호 건 제외·보고. 둘 다 인메모리 테스트로 검증.
- p_rule 교체 경로: reviews ≥20건인 규칙은 `(violations+1)/(reviewed+2)`를 `p_rule`에 기록하고 weak.yaml 버전↑. prior는 무작위 표본 위반율로 교체.
- 학습 시 합성 행 제외는 모델 단계에서 `JOIN tx_active … WHERE NOT is_synthetic`으로 강제한다.

## 구현 기록 — models v1 (2026-11-01)
- 파일: `models/base.py`(Scorer 규격 fit/predict/explain, DEMO_DISCLAIMER, ablation_explain), `baseline.py`(규칙 수×log금액, aux만 사용), `logistic.py`, `xgb.py`(xgboost, 실패 시 sklearn HGB 폴백), `dnn.py`(빈 자리), `scripts/train.py`, `scripts/score_tx.py`, `tests/test_models.py`(27개 전체 통과).
- 시험: train 1~2월 6,836건(양성 579) / test 3월 22,597건(양성 2,801), weak 라벨 ≥0.5 이진화, 합성 제외, lookahead 4열 제외, 규칙 열은 aux로만.
- 결과: 기준선 p@100 1.00 · PR-AUC 0.999 / 로지스틱 0.88 · 0.660 / XGBoost 1.00 · 0.812. 기준선과 top-100 겹침: 로지스틱 4%, XGBoost 3%.
- **해석.** weak 라벨은 규칙 투표의 함수이므로 "규칙 수×금액" 기준선은 답지를 재현한다(PR-AUC 0.999). 이 시험에서 기준선은 구조적으로 질 수 없다 → 선택 규칙대로 `chosen=baseline`. 의미 있는 결과는 **규칙을 못 보는 XGBoost가 행동 피처만으로 규칙 합의를 PR-AUC 0.81로 복원했고 상위 100건은 기준선과 3%만 겹친다**는 것(다른 눈으로 같은 결론). 그래서 `best_learned`를 `model_learned.pkl`로 함께 저장하고 `tx_score`에 `score`(채택 모델)와 `score_learned`(학습 모델)를 둘 다 둔다. 화면 기본 정렬은 기준선, "학습 모델 점수 (시연용)"는 명시적 옵션, 규칙 밖 고점수(`service.top_unflagged_by_score`)는 학습 점수로.
- 규칙 밖 고점수 상위 예: PG(11번가) 59,000 / 해외 전기요금 69,857 / 해외 게스트하우스 203,660 — 발굴 루프 입구 2의 첫 후보들.
- #11012 학습 점수 0.94, 이유: 휴가 1 · 같은 계정×업종 과거 거래 1건 · 출장 아님.
- 진짜 승부는 reviews 라벨에서: `train.py --label-source reviews --reviewers …`로 같은 시험을 다시 치르면 그때 기준선 대비가 의미를 가진다.
- 거부한 대안: weak prob 회귀/가중(규칙 수 베끼기로 회귀), 무작위 분할(사람 누수), 기준선 없는 선택.
