# 검토 화면 사양 (프런트 요구사항) — 2026-10-31

Streamlit 임시 구현(`app/pages/1_플래그_검토.py`)은 버려져도 이 사양과 `app/service.py`는 남는다. 근거: `research_notes/audit_review_ui_references*.md` (Stripe Radar, Ramp, Brex, Expensify, Concur Verify, HighBond, MindBridge, SAS, 국내 감사 점검표).

## 원칙
1. 한 번에 한 질문, 조사관의 사고 순서대로. **결론(무엇이 얼마나 의심되나) → 맥락(그날·금액) → 해석(규칙별 관측값 vs 기준) → 근거(규정·문서) → 제2의견(모델)**. 대부분은 결론과 맥락에서 끝나야 한다. (2026-11-06 개정. 이전 "규정 → 정황 → 반복"은 규정을 먼저 읽게 해 뒤의 자료를 확인용으로만 보게 만들었다.)
2. 이유는 코드가 아니라 문장. 결론 한 줄 + 숫자 한 줄 + 근거 규정 한 줄. 결론 줄은 **"위반이다"가 아니라 "걸린 개수 + 가장 센 것 한 문장"** — 판정은 사람이 내리므로 시스템이 결론을 먼저 말해 앵커링하지 않는다.
3. 심각도는 두 가지. 🔴 위반 가능(규정 근거 있음) / ⚪ 참고(통계·가설). 등급은 `packs/corp_card/rules/catalog.yaml`의 `tier`.
4. 판정은 거래 단위, 버튼 셋. 위반 / 아님 / 보류. "아님"일 때만 사유 필수. 자동 진행 없음, "다음 건" 버튼.
5. 모든 결정은 이력으로 남고 덮어쓰지 않는다(`reviews.superseded_by`).

## 셸 구조 (2026-11-04, React `web/`)
shadcn 공식 패턴 둘의 조합: **"사이드바가 사이트 헤더 아래에 들어가는" 패턴 + `variant="inset"`**.
- **바탕**(`bg-sidebar`, 한 단계 어두움): 상단 헤더 띠(트리거 · 섹션 제목 · ⌘K 자리)와 아이콘 **레일**(섹션 4개 + 하단에 테마 전환 · 사용자). 테마 전환은 다크↔라이트 원 버튼으로 `D` 키와 같은 동작(`theme-provider.tsx`의 `toggleTheme`). 기본값 `system`(OS 따름)은 한 번 누르면 고정되고, UI로 되돌리는 경로는 두지 않았다.
- **카드**(`SidebarInset`, 둥근 모서리·그림자): 안에 **목록 패널**(20rem, 현재 섹션의 목록) + **메인**(선택 항목 내용)이 한 면으로.
- 레일은 shadcn 사이드바를 **접힘 상태로 고정**(`SidebarProvider open={false}`)해 항상 48px 아이콘 레일. 목록 패널은 **별도 상태**(`components/panel-state.tsx`, localStorage 저장, ⌘B·헤더 토글). 두 개념을 한 상태로 묶으면 패널을 여닫을 때마다 레일 버튼이 펼침↔접힘 스타일 사이를 전환해 출렁인다(2026-11-04 수정, CDP 실측으로 아이콘 위치 불변 확인). 모바일에서 토글은 레일 시트를 연다.
- 섹션: 검토 `/review` = 큐 목록, 데이터 `/data` = 적재·큐 이력, 규칙 `/rules` = 규칙 목록, 요약 `/summary` = 패널 없음.
- 상태는 전부 URL: 활성 섹션 = 첫 경로 조각(`components/sections.tsx` `useActiveSection`), 선택 = 파라미터(`/review/$txId`, `/rules/$ruleId`). 전역 스토어 없음.
- 목록 행 배지는 글자만("위반 n", "참고 n", "모델 추천", "무작위 표본", "위반 처리"). 이모지 없음. 거래 식별은 전표번호, tx_id는 URL에만.
- 파일: `app-shell.tsx`(배치), `app-sidebar.tsx`(레일), `section-panel.tsx`(카드 안 목록 열), `site-header.tsx`(헤더 띠), `lists/*`(섹션별 목록).

## 케이스 패널 v2 (2026-11-04) — 객체·속성·관계
거래를 "문장"이 아니라 **객체**로 보여준다(팔란티어 Object View 관점). 사실은 속성 격자에 한 번만, 규칙 적중은 "관측값 vs 기준" 표로, 관계는 탭으로.

```
속성 격자   금액·일시 / 가맹점·업종(시군구) / 사용자·승인자 / 계정·전표·첨부·적요     ← 모든 사실은 여기 한 번
결론 한 줄  "주거지 인근(용인시 수지구) 사용, 근무지와 다른 지역 · 그 밖에 …"  + 위반 n · 참고 n 배지  (금액·업종 반복 없음)
차트 ①     금액 분포: 본인 / 동료 두 줄 (25–75% 띠, 90% 점, 이 건 세로선) + 숫자(이 건 · 본인 중앙값 ×배 · 동료 상위 %)
근거 표     등급 | 규칙 | 관측값 | 기준 | 근거(규정 인용)      ← lib/findings.ts 가 규칙별 evidence 필드를 두 칸으로 매핑
탭          그날[차트 ②] · 이 사람[차트 ③ + 과거 거래·적중·최근 5건] · 승인자 · 비슷한 사례 n · 함께 볼 거래 n · 모델
판정 바     위반(주) · 아님 · 보류 + 단축키 · 현재 판정 · 출처(규칙 v · 모델 v · 큐 기간)
```
규칙 없는 건(모델·무작위): 결론 자리에 출처 문구, 근거 표 생략, 차트 ①이 주 근거.

## 케이스 패널 v3 (2026-11-06) — 다섯 층
v2(위)는 "객체·속성·관계"로 사실은 잘 정리했지만, 속성 8칸·표 5열·탭 6개를 매 건 읽어야 했다. v3는 **읽는 화면에서 넘기는 화면으로**: 층마다 한 질문, 위에서 아래로 조사관의 순서. 글자 대신 UI(셰브론·숫자 배지·눌린 버튼), 빈 섹션은 그리지 않음, 질문형 제목 금지. 갤러리 `/gallery`에서 v2와 나란히 비교.

|---|---|---|---|---|

| 공통(접힘) | 처음인가 반복인가 | 이 사용자 이력(과거 결제 n · 규칙에 걸림 n · 위반 판정 n, 13주 막대) · 전표 정보(전표·계정·승인자·적요) | `history`, `profile.weekly`, 거래 | 접힌 섹션 |
