# 진행 순서

| # | 단계 | 무엇을 만드나 | 방식 | 완료 기준 | 선행 |
|---|---|---|---|---|---|
| 0 | 데이터 이해 | 시트 인벤토리, 열 프로파일, 키 매칭률 | 스크립트 | ✅ 완료 (`data/inventory/`) | - |
| 1 | 표준 적재 | DuckDB에 거래·사용자·출입·규정 테이블 | 금액 변환, 취소 제외, 계정 매핑표, 출입 연결 | ✅ 완료 (`scripts/load.py`, 지오코딩은 API 키 후) | 0 |
| 2 | 합성 정답셋 | 징계사례 22건을 거래에 심은 테스트 데이터 | 시나리오별 위반 삽입, 정답 목록 저장 | ✅ 완료 (`scripts/synth.py`, `scripts/score.py`, 20사례·79건) | 1 |
| 3 | 규칙 엔진 | 규칙 19개 + 출력 계약 | 파라미터화된 SQL, 규칙 버전 기록 | ✅ 완료 (`rules/`, `scripts/run_rules.py`, 합성 재현율 100%, 임계치는 미확정 → `docs/RULES.md`) | 1, 2 |
| 4 | 검토 화면 | 플래그 목록, 케이스 상세, 결정·사유 저장 | Streamlit 임시 화면 + `app/service.py` | ✅ 임시 버전 완료 (reviews 테이블에 라벨 저장). 정식 프런트는 UX 확정 후 | 3 |
| 4.5 | 선례(유사 사례) | 징계사례 22건 → precedents 테이블, 규칙 서명 유사도, 1층 칩 | 설계 `docs/PRECEDENTS.md` | 합성 거래의 출처 사례 1위 비율 ≥ 80% | 3, 4 |
| 5 | 자연어 입력 | 질문 → 시나리오+파라미터, 제한 SQL 폴백 | LLM 슬롯 채우기, 쿼리 화면 노출 후 실행 | 골든 질문 30개 정확도 측정 | 3 |
| 6 | 근거 서술 | 플래그별 한국어 근거 문장 | LLM이 규칙 출력 필드만 인용, JSON 강제, 숫자 검증 | 인용 숫자 100% 원본 일치 | 3 |
| 7 | 증빙 파이프라인 | OCR 추출, 거래 대조, 결정적 포렌식 | CLOVA/Upstage + 코드 대조, 해시·PDF 리비전·메타데이터 | 별도 영수증 샘플로 대조·위조 탐지 시연 | 1 (독립 진행 가능) |
| 8 | 우선순위 모델 | 시연용: 합성 라벨로 학습 → 점수 → 정렬. 운영: 윤경팀 판정으로 재학습 | 설계 `docs/MODEL.md`. 라벨 출처를 인자로 강제 | 시간순 검증 상위 K 정밀도 > 단순 정렬 | 3 (시연), 4의 라벨 (운영) |
| 9 | 신규 패턴 발굴 | LLM 규칙 초안 → 백테스트 → 승인 | 동료집단 이상치를 LLM에 제시 | 제안 규칙이 3의 엔진에 등록됨 | 3, 6 |
| 10 | 부가 분석 | 사람·부서 프로필, 승인자 프로필, 추세 | 집계 쿼리 + 차트 | 검토 화면에 맥락 패널로 표시 | 1 |

병렬 가능: 1→2→3 이 주축. 4는 3의 스키마만 정하면 바로. 7은 1과 독립. 5·6·9는 3 뒤. 8은 맨 마지막.
