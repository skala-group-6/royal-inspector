# 06. 영국 정부 경비 탐지기 — ATRS(알고리즘 투명성 기록 표준)에 공개된 사기·이상 탐지 도구

> 조사일 2026-11-02. 출처 등급: [공식문서](ATRS 기록·gov.uk 정책·IPSA 공식 페이지) [정부보고서](NAO·PSFA·GIAA 연차보고) [2차](언론·연구). 확인 못 한 항목은 ⚠️ 표기.
> 조사 결과 요약: ATRS 155건(2026-11 기준, 4페이지) 중 **법인카드·경비를 직접 겨냥한 기록은 1건 — DBT(기업통상부) "Expenses Fraud Detector"** 만 존재한다. GIAA·PSFA·NHSCFA·DfE·MoD의 경비 이상탐지 ATRS 기록은 **없다**. 대신 사기·이상탐지 구조를 보여주는 인접 기록 5건(DWP UC Advances, HMRC VAT Returns Analysis, DfT EV Chargepoint Photos, PSFA FRA Accelerator, Salix FRA Reviewer)을 함께 해부했다. IPSA(의원 경비)는 ATRS 대상이 아니지만 "전부 공개 → 대중 감시"라는 다른 설계로 별도 정리했다.

## 0. 한 장 요약

영국 중앙정부는 2024-02부터 "결정에 유의미한 영향을 주는 알고리즘 도구"마다 ATRS 기록(데이터·모델·사람 개입·성능·위험)을 gov.uk에 공개해야 한다. 그 안에서 우리 문제와 같은 도구는 DBT의 경비·GPC 위반 탐지기 하나뿐이고, **그것은 ML 없는 순수 룰 기반 Python**이다.

- **DBT 탐지기 = 우리와 거의 같은 설계.** SQL로 경비·GPC 데이터를 꺼내 Python으로 정책 룰을 적용, 룰별 1/0 플래그 표를 Streamlit 대시보드에 띄움. Isolation Forest·Random Forest를 시험했지만 "설명 불가·라벨 부족"으로 룰로 회귀. 월 수만 건, 개발 데이터 4만 행, 모든 출력은 사람이 검토.
- **ATRS가 강제하는 것은 알고리즘이 아니라 '설명 책임의 서식'.** 소유자·데이터 출처·민감속성·모델 종류·사람 개입 지점·성능 측정법·위험 3개와 완화책을 같은 칸에 적게 한다. 이 서식 자체가 우리 산출물 후보다.
- **성능 수치는 거의 없다.** 6건 중 정량 수치가 있는 것은 DWP(무작위 대조군 대비 2.5배)와 Salix(1차 통과율 88% vs 사람 91%) 둘. DBT는 "precision/recall 적용 불가"라고 적었다. 정부 기록도 벤더 마케팅과 다르게 **"모른다"를 쓴다**.
- **DWP 사례가 보여준 함정**: 17개 필드를 FOIA s31로 가리고 2년 버틴 끝에 공개된 기록은 "탐지 효과 미달·재학습 필요", 3년간 직접 절감 500만 파운드 미만, 비UK 국적·35세 이상 과다 조회. **공개 거부가 신뢰를 더 깎았다.**
- **IPSA는 반대 설계**: 전 청구 공개 + 사전 샘플 + 사후 패턴 검토 + 주제별 리뷰 + 30일 상환. 탐지기가 아니라 "공개가 통제"인 모델. 우리 윤리경영팀 맥락에선 공개가 불가능하므로 **내부 공개(룰 카탈로그·판정 통계)로 치환**해야 한다.

## 1. 한 줄 정의

**ATRS(Algorithmic Transparency Recording Standard)** 는 영국 DSIT(과학혁신기술부)가 운영하는 공개 템플릿으로, 중앙정부 부처가 "공공에 영향을 주는 결정 과정에 유의미한 영향을 주거나(significant influence) 대중과 직접 상호작용하는" 알고리즘 도구를 Beta/Pilot·Production 단계에서 기록·공개하도록 2024-02-06부터 의무화했다(Phase 1: 대부분 장관급 부처 + HMRC, Phase 2: 나머지·ALB). [공식문서] 그 중 **DBT Expenses Fraud Detector**는 기업통상부 재무거버넌스팀이 월 수만 줄의 경비·GPC(정부구매카드) 청구를 정책 룰로 걸러 사람에게 넘기는 내부용 룰 엔진이다. [공식문서]

## 2. 데이터 입력

### 2.1 DBT Expenses Fraud Detector [공식문서]
- **소스**: "GPC MI data, tabular" — DBT의 GPC·경비 거래. 수집 주체는 공유서비스기관 **UKSBS**의 경비 포털(직원이 경비를 제출할 때 생성). 즉 카드사 피드가 아니라 **경비 시스템 추출물**이다.
- **범위**: 과거 5년, 구 DIT 데이터 포함. 2023년 합병 전 BEIS 출신 직원의 과거 데이터는 **제외** — 조직 통합 경계가 곧 데이터 공백.
- **민감속성**: 직원·승인자 이름, 직원번호. 학습·테스트 중엔 익명(직원번호만), 배포 대시보드에서만 이름 표시.
- **전처리**: 기록에 적힌 것은 "날짜 문자열 → datetime 변환" 하나.
- **없어서 못 하는 것**: "여행지 기온 데이터가 없다"(leisure 지출 판정에 쓰고 싶었던 외부 데이터). 성능 한계 원인으로 명시.
- **보관·공유**: Data Workspace(AWS)에 5년 보관, 접근은 재무거버넌스팀 + 일부 DDaT. **GIAA(정부내부감사청)와 데이터 공유 협약** — 확정된 사기 건은 GIAA로 넘김.

2010년 연립정부 투명성 기준에 따라 각 부처는 **GPC 500파운드 초과 거래를 월별 CSV**로 gov.uk/data.gov.uk에 공개한다(HMT·FCDO·DfE·CPS·IPO 등; IPO는 2026-06 분까지 게재 확인). 이 공개 데이터를 **분석하는 정부 도구·대시보드는 발견되지 않았다** ⚠️. 필드 구성(가맹점·금액·일자·구분)은 CSV를 직접 열지 않아 미확인 ⚠️.

## 3. 구성요소와 흐름

DBT 기록의 시스템 아키텍처 필드를 그대로 그리면 다음과 같다. [공식문서]

```
 UKSBS 경비 포털 (직원 제출)            UKSBS 자체 out-of-policy 플래그
        │ 월말 데이터 적재                       │ (기존, 병행 유지)
        ▼                                        │
 DBT Data Workspace (AWS)                         │
 ┌─────────────────────────┐                     │
 │ SQL: 경비·GPC 데이터셋 조회 │                     │
 └──────────┬──────────────┘                     │
            ▼                                    │
 ┌─────────────────────────┐  룰 = "경비정책을 코드로 옮긴 것"
 │ Python 룰 엔진 (GitLab)  │  + 기타 지표(예: leisure 지출)
 │  룰마다 출력 1 / 0        │  가중치 부여는 "계획"
 └──────────┬──────────────┘
            ▼
 ┌─────────────────────────┐
 │ Streamlit 대시보드(Docker)│  거래 상세 표 + 룰별 위반 플래그 열
 └──────────┬──────────────┘                     │
            ▼                                    ▼
 재무거버넌스팀 사람 검토 ──── 원시 데이터와 대조 ──── 조치 결정
            │
            ▼
 사기 확정 → GIAA 이관(데이터 공유 협약) / 상환 요청(사전 통지 후, 자동 벌칙 없음)
```

- **룰 → 플래그 → 표**. 점수도 순위도 없다. "weighting of rules is planned"가 유일한 우선순위 계획.
- **기존 대시보드와 병행**: 이전 프로세스(일반 지출 추세 + 일부 정책 룰 대시보드)와 UKSBS 플래그를 **대체하지 않고 옆에 둔다**.
- **빈도**: "월말 데이터 적재 후, 월 수 회" — 실시간이 아닌 월 배치.

인접 기록의 흐름 차이: DWP는 **결제 전** API 호출 → 고위험이면 사람 심사(대조군 무작위 의뢰와 섞어 보냄). HMRC는 담당관이 **조회할 때만** STL+IQR 계산. DfT는 **백로그 배치** 후 플래그만. [공식문서]

## 4. 판단 방식

### 4.1 DBT: 룰만, 모델 시도는 기각 [공식문서]
- "The algorithm is entirely rules-based and doesn't use any machine learning or statistical models."
- 대안 검토 필드: **Isolation Forest와 Random Forest를 테스트** → "poor explainability and inconsistent accuracy", "limited labelled data" → "felt it better to stick with a more straightforward encoding of the rules." 우리 ROADMAP의 "약한 라벨 → 모델 정렬" 단계가 정확히 이들이 포기한 지점이다.
- **설명**: 별도 생성 없음. 룰 이름 = 설명. 플래그가 선 거래를 사람이 원시 데이터와 대조.
- **사람 개입 선언문**(ATRS 서식 그대로): "there is no solely automated processing involved, all decisions are taken after thorough human investigation" / "No decisions are automated." 조치 전 **항상** 팀원 검토.
- **이의 제기**: 자동 처리가 없으므로 별도 절차 없음. DBT 경비정책에 따른 검토, 사용자는 개발자에게 피드백 가능.

### 4.2 인접 기록의 판단 구조 [공식문서]
| 기록 | 모델 종류 | 출력 | 사람 개입 문구 | 설명 방식 |
|---|---|---|---|---|
| DWP UC Advances | 지도학습 이진 분류(아키텍처 비공개) | 사기 확률 → 고위험 의뢰 | "always a human intervention… no automated decision making" / 심사자는 **점수를 받지 않고, 모델이 보냈는지도 모름** | 심사자에게 설명 안 함(블라인드 설계) |
| HMRC VAT Returns | STL 분해 + IQR(R timetk) | 기대값 vs 관측값, 이상 기간 표시 | "No decisions are made by the tool" | 그래프·표로 기대-관측 차이 제시 |
| DfT EV Photos | CNN 임베딩 중복 + Google Vision 웹 검색 | 중복/웹 출처 플래그 | "A human still always makes the final decision"; 매치를 그냥 수락 못 하고 수동 확인 필수 | 매칭된 사진 쌍 제시 |
| PSFA FRA Accelerator | Azure OpenAI GPT 5.2 + ada-002 임베딩 | FRA 초안(Actor/Action/Outcome) 엑셀 | "qualified Fraud Risk Assessor will evaluate" | 초안 자체 |
| Salix FRA Reviewer | Copilot 내 LLM + "결정적 로직"(기술 모순 있음) | 체크리스트별 충족/미충족 + 근거 + **인용 증거** | "Human quality control is performed on every output" | 항목별 rationale + cited evidence |

핵심 관찰: 6건 **모두** "사람이 최종 결정" 문구를 같은 필드(Human decisions and review)에 적는다. 하지만 **사람이 무엇을 보는지**는 갈린다 — DBT·Salix·HMRC는 근거를 보여주고, DWP는 의도적으로 **숨긴다**(점수 편향 방지).

## 5. 피드백

- **DBT**: 판정 결과가 룰로 되돌아가는 경로는 "Updates are made on stakeholder request", "users can give feedback to developers" 뿐. 판정 저장소·라벨 축적 언급 **없음**. 사기 확정 건은 GIAA로 이관되지만 그것이 룰 개선에 쓰이는지는 기록에 없음 ⚠️.
- **DWP**: 사람 심사 결과(승인/거절)가 다음 학습의 타깃. "The model has been retrained, but further testing is required ahead of the retrained model going live." 재학습은 있으나 **배포 전 검증 단계에서 멈춤**.
- **DfT**: "tracks true and false positives on an ongoing basis", 처리자 피드백으로 개선. 수치는 미공개.
- **Salix**: 분기 정기 검토 + 사용자 피드백 ad hoc 검토. 분석가의 override는 리스크 문서에 기록.
- **HMRC·PSFA**: 피드백 경로 기술 없음(정성적 SME 피드백만).
[공식문서]

## 7. 구조적 한계 — 기록 자체가 말하는 것

1. **룰 전부, 우선순위 없음(DBT)**: 1/0 플래그 표에 가중치가 없어 "월 수만 건 중 어디부터 볼지"는 사람이 정한다. "weighting… planned"가 그 증거. 자주 출장 가는 직원이 오탐된다고 Risk 3에 스스로 적음.
2. **라벨 부족 → 모델 포기(DBT)**: Isolation/Random Forest가 실패한 이유가 "limited labelled data". 판정을 저장·축적하는 장치가 기록에 없으니 이 한계는 **구조적으로 해소되지 않는다**.
3. **외부 데이터 결손(DBT)**: 기온 등 맥락 데이터 부재를 성능 한계로 명시. 룰이 정책을 그대로 옮긴 것이라 정책에 없는 패턴(쪼개기·주말·동일 가맹점 반복)이 룰에 있는지는 기록에서 확인 불가 ⚠️.
4. **조직 경계 = 데이터 경계(DBT)**: BEIS 출신 직원 과거 데이터 제외. 합병·조직개편 시 이력 기반 룰(반복자)이 끊긴다.
5. **월 배치·사후(DBT)**: 지급 후 상환 요청 구조. 승인 시점 차단은 범위 밖.
6. **비공개가 신뢰를 깎음(DWP)**: FOIA s31로 17개 필드 비공개. 공개된 뒤에도 "untestable for discrimination"(Amnesty), 비례성 의문(PLP). 비용 미공개. **사기 탐지라는 이유로 가리면 외부 검증이 불가능해지고, 그 자체가 비판 대상이 된다.**
7. **"사람이 최종 결정"의 공허함**: 6건이 똑같은 문구를 쓰지만 검토자가 하루 몇 건을 어떤 근거로 보는지, 번복률이 얼마인지는 어느 기록도 적지 않는다. 문구는 의무이고 실측은 아니다.
8. **기록 자체의 품질 편차**: DBT 기록은 존재하지 않는 절 "2.2.4"를 참조하고, 완화책(직원번호만 처리)과 설명(배포 시 이름 표시)이 상충. Salix는 "결정적 로직"과 "LLM"을 동시에 주장. PSFA는 Phase 표기가 Public/Private Beta 혼재. **템플릿이 있어도 내용 정합성은 보장되지 않는다.**

### 7.1 IPSA — "공개가 탐지기"인 반대 설계 [공식문서][정부보고서]
- 3단 검증: ① **지급 전** 샘플 검증(무작위 + 고위험 유형: 고액 전문서비스·장비 우선) ② **지급 후** 의원 단위 맥락 검토(이상 패턴·아웃라이어·중복·반복 오류) ③ **주제별 보증 리뷰**(전 의원 집계, 한 카테고리·기간 집중; 결제카드 사용 2020, 전문서비스 2019, 재임대 2019, 총선 2015/2017/2019 등). 보증팀은 검증팀과 **분리**.
- **전 청구(지급·미지급 포함) 2개월 단위 공개** — "one of the most important safeguards". 유권자·언론이 검출기.
- 상환 30일, 미이행 시 향후 청구에서 공제·결제카드 정지. 독립 Compliance Officer가 누구의 민원이든 접수.
- NAO(2011): 반려율이 낮고 체계적 남용이 없으니 "검증 노력을 위험 영역에 집중하라" 권고. 의원 85%가 경비 처리 시간이 과다하다고 응답. 사전 검증 샘플 비율·연간 반려 건수는 Annual Review of Assurance PDF에 있을 것으로 보이나 **미열람** ⚠️.

## 8. 우리에게 주는 것

ATRS에서 가져올 것은 알고리즘이 아니라 **문서 서식과 운영 약속**이다. 우리 시스템(룰 카탈로그 + 룰별 SQL, 무작위 샘플·출처 포함 리뷰 큐, 약한 라벨 → 모델 정렬, 정책 인용 증거문장, 대학 윤리경영팀)에 다음을 반영한다.

### 8.1 가져올 것
| # | 영국 장치 | 우리 반영 | 우선 |
|---|---|---|---|
| A | **ATRS 기록을 산출물로** — 소유자/데이터 출처·민감속성·보관/모델 종류/사람 개입/성능 측정법/위험 3개+완화책/DPIA | `docs/transparency_record.md` 1장을 납품물에 포함. 윤리경영팀장이 소유자 칸에 서명. 외부 공개 아닌 **교내 공개** | **상** |
| B | **룰 = 정책의 코드화**(DBT) + 룰 카탈로그 공개 | catalog.yaml 각 룰에 `policy_ref`(학교 규정 조항) 필수 필드. 룰 목록·임계치를 윤리경영팀·감사 대상 부서가 볼 수 있게 — IPSA식 "공개가 통제"의 내부판 | **상** |
| C | **사람 개입 선언문 서식** — "No decisions are automated. 모든 조치는 검토자가 원시 데이터와 대조 후 결정" | 리뷰 큐 상단과 산출 보고서 머리말에 고정 문구. 단, 영국 기록이 못 한 **실측(검토 건수·번복률·검토 시간)을 월별 수치로 함께 표기** | **상** |

### 8.2 피할 것
- **플래그 1/0 표만 내놓는 것**(DBT): 월 수만 건에서 우선순위가 없으면 사람이 다시 전수 검토한다. 우리 모델 정렬이 바로 이 구멍을 메우는 것이므로 **포기하지 말고, 약한 라벨을 쌓는 리뷰 저장소를 1급 구성요소로** 둔다(DBT는 라벨이 없어 모델을 포기했다).
- **"사기 탐지라서 비공개"**(DWP): 룰 상세를 가려 회피를 막겠다는 논리는 외부 검증 불능이라는 더 큰 비판을 불렀다. 룰 카탈로그는 공개하고, 회피 우려가 큰 **임계치 수치만** 비공개 가능하게 분리(03의 thresholds.yaml 분리와 일치).
- **선언만 있는 "사람이 최종 결정"**: 번복률·처리기한 수치 없이 문구만 두면 ATRS 6건과 같은 공허함. 03의 보류 기한(30일)과 함께 **검토 실적을 기록에 넣는다**.
- **기록과 구현의 불일치**(DBT 2.2.4 참조 오류, 익명화 상충): 투명성 기록을 손으로 쓰지 말고 catalog.yaml·schema에서 **생성**해 어긋나지 않게 한다.
- **조직 경계로 이력 끊기**(DBT BEIS 제외): 부서 개편·학과 통합 시 사용자 ID 매핑 테이블을 유지해 반복자 추적이 끊기지 않게.
- **외부 맥락 데이터 의존 룰**(DBT 기온): 외부 데이터가 없을 때 룰이 조용히 비활성화되지 않도록, 룰마다 `requires` 데이터 목록과 결손 시 "평가 불가" 상태를 출력.
