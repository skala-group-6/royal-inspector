# 프로젝트 정의 요구사항서 — 법인카드 사용 점검 지원 시스템

문서 버전 0.1 (2026-11-01) · 상태 열: ✅ 구현됨 / 🔧 설계됨(문서·코드 일부) / ⬜ 예정

## 1. 프로젝트 목적
윤리경영팀이 연 약 30만 건의 법인카드 거래를 수작업(연 12MM)으로 점검하는 현재 방식을, **기계가 전수 검사해 의심 거래를 근거와 함께 추려 주고 사람은 판정만 하는 방식**으로 바꾼다. 사람의 판정은 기록되어 시스템을 계속 개선하는 재료가 된다.

## 2. 배경과 문제
- 사적 사용(개인 물품, 휴일 사용 등)과 절차 위반(증빙 누락, 카드 대여 등)이 실제로 발생한다.
- 수작업 전수 점검은 1년치에 12MM이 들고, 사람 눈으로는 증빙 불일치나 파일 변조를 놓친다.
- 기존 상용 솔루션은 자사 경비 흐름 안의 거래만 감사하며, 엑셀 사후 감사·한국어 영수증·국내 규정을 지원하지 않는다(별도 조사 보고서 참조).
- 최근 국내 적발 사례(주말 사용 3,593건, 50만원 쪼개기 103건 등)는 모두 단순 규칙으로 잡히는 패턴이었으나 아무도 규칙을 돌리지 않았다.

## 3. 범위
### 3.1 범위 안
| 영역 | 내용 |
|---|---|
| 입력 | 카드 거래 엑셀(HR 정보 포함), 사옥 출입기록 엑셀, 계정별 비용정산지침, 징계사례 |
| 탐지 | 사전 정의 시나리오 12종에 대한 규칙 기반 전수 검사, 근거 문장과 규정 인용 |
| 우선순위 | 통계·학습 모델로 의심 거래의 검토 순서 결정(판정은 하지 않음) |
| 검토 | 사람이 한 건씩 판정(위반/아님/보류)하는 화면, 결정 이력 저장 |
| 선례 | 징계사례와 과거 판정 중 규칙 서명이 겹치는 것을 참고로 제시 |
| 개선 | 판정 결과의 환류(라벨), 무작위 표본과 회피 변형으로 규칙 공백 발견, 새 규칙 제안·승인 |
| 질의 | 자연어 또는 사전 명령으로 점검 조건을 지정 |
| 증빙 | 영수증 OCR 대조, 파일 위변조 신호(해시·메타데이터·픽셀) |

### 3.2 범위 밖
- 위반 여부의 자동 확정과 징계 처분 결정(사람 몫)
- 실시간 결제 승인 차단
- 카드사·ERP 시스템 직접 연동(엑셀 업로드로 대체)
- 참석자 등 원천 데이터에 없는 정보의 생성

## 4. 이해관계자
| 역할 | 주요 관심 |
|---|---|
| 윤리경영팀 감사자 | 봐야 할 건수, 근거의 명확성, 판정 기록 |
| 윤리경영팀 관리자 | 규칙별 적중률, 임계치 확정, 새 규칙 승인, 경영 보고 숫자 |
| 개발팀 | 재현 가능성, 테스트, 확장(모델 교체, DB 전환) |

## 7. 제약과 가정
- 제공 데이터에는 정답(위반 여부) 라벨이 없다. 시연용 모델은 규칙 투표 임시 정답으로 학습하며 실제 성능이 아님을 명시한다.
- 임계치는 규정이 아니라 도구 설정이다. 개발팀이 초기값을 정하고 윤리경영팀이 처리 가능 건수에 맞춰 확정한다.
- 영수증 파일은 거래 데이터와 연결되지 않은 별도 샘플이다. 증빙 기능은 샘플로 파이프라인을 시연한다.
- 참석자·회의 정보는 원천 데이터에 비어 있다. 카드 대여·업무 연관성은 후보 추출까지만 가능하다.
- 실데이터 하이패스 거래에는 위치가 없어 경로 규칙(R17)은 합성에서만 검증된다.

## 8. 성공 기준
| 기준 | 측정 |
|---|---|
| 검토 대상 축소 | 전수 대비 검토 건수 비율(현재 29%, 임계치 확정 후 재측정) |
| 규칙 신뢰성 | 합성 정답셋 재현율 100%, 회피 변형 커버리지 |
| 순서 품질 | 상위 K건 확정률이 단순 정렬보다 높음 |
| 개선 루프 | 무작위 표본 위반 발견 → 규칙 승격까지의 경로가 동작 |
| 사용성 | 첫 층(근거 문장)만으로 판단이 선 건의 비율 |
