# 설계서 — 법인카드 사용 점검 지원 시스템

문서 버전 0.1 (2026-11-01). UI·API·DB 명세와 요구사항 추적표. 요구사항 ID는 `01_요구사항서.md`, 구성요소 번호는 `03_아키텍처정의서.md`.

## 1. UI 설계

### 1.1 원칙 (업계 검토 화면 공통 패턴 기반: Stripe Radar, Ramp, Concur Verify, 국내 감사 점검표)
1. 한 번에 한 질문: 1층 "규정에 어긋나나" → 2층 "정황이 뒷받침하나" → 3층 "반복인가". 대부분 1층에서 끝난다.
2. 이유는 코드가 아니라 문장: 결론 한 줄 + 숫자 한 줄 + 근거 규정 한 줄.
3. 심각도 2단계: 🔴 위반 가능(규정 근거) / ⚪ 참고(통계·가설).
4. 판정은 거래 단위, 버튼 셋(위반/아님/보류). "아님"일 때만 사유 필수. 자동 진행 없음.
5. 모든 결정은 이력으로 남고 덮어쓰지 않는다.

## 2. API 설계
현재는 파이썬 함수(`app/service.py`)로 구현되어 Streamlit이 직접 호출. 정식 프런트에서는 같은 함수를 FastAPI로 노출.

### 2.1 공통 객체
- `FlagSummary`: tx_id, tx_ts, emp_id, emp_name(마스킹), dept, rank, account_policy, merchant, mcc_name, total, rules[], n_rules, sev, review_status, is_synthetic
- `Evidence`: rule_id, rule_name, rule_class, severity, evidence(JSON), evidence_text, related_tx[], rule_version
- `Review`: review_id, tx_id, rule_id, decision, reason_code, memo, reviewer, created_at, superseded_by
- `Precedent`: precedent_id, kind, title, summary, cues[], outcome, source, score, overlap[], only_in_precedent[], only_in_tx[]
